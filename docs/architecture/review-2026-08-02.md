# Kod- och databasgranskning 2026-08-02

## Utgångsläge

Repositoryt var en säker greenfield-grund, inte den kompletta KommunSign-produkt som målbilden beskriver. Byggkedjan och sju kärntester var gröna när TypeScript kunde göras tillgängligt, men flera produktionskritiska luckor fanns.

## Kritiska fel som korrigerades

### TIC/BankID

- poll/collect/cancel använde inte verifierad HTTP-semantik,
- `userNonVisibleData` skickades inte som den Base64-representation som providerkontraktet kräver,
- providerfält för QR/subscription/order kunde gå förlorade,
- URL- och timeoutskydd var otillräckliga,
- collect-resultatet var inte strikt bundet till förväntad session.

### API

- interna fel kunde läcka till klient,
- routes saknade konsekvent auktoriseringskontroll,
- JSON accepterade okända fält och saknade tydlig bytegräns,
- send/cancel saknade samma idempotenskrav som create,
- Docker-startkommandot startade inte en verklig säker runtime.

### Databas och workflow

- korskoppling mellan olika ärenden var möjlig i flera relationer,
- låsta dokument- och policybindningar kunde ändras efter start,
- terminala statusar saknade fullständig evidence-kontroll,
- digitalt godkännande och kryptografisk underskrift delade för svag completion-regel,
- kraschade worker-jobb kunde fastna efter utgången lease,
- audit-hash täckte inte alla säkerhetsrelevanta fält.

### Freja/JWS

- verifieraren behövde striktare algoritm- och nyckelbindning,
- ES256 JOSE-signaturformat behövde konverteras korrekt för Java-verifiering,
- kritiska JWS-headerbeteenden behövde avvisas fail-closed.

### Proveniens

- 85-procentsgrinden kontrollerade inte faktisk LOC-andel,
- tillståndsbevisets existens och SHA verifierades inte,
- donor-repositories var inte låsta till aktuella exakta commits,
- det saknades en maskinläsbar file-to-file reuse-map.

## Resultat

- 18 kärntester är gröna.
- Java JWS self-test är grönt.
- Donorgrinden är grön med 0 importerade donor-LOC och åtta exakta pins.
- API-runtimen är fail-closed tills riktiga dependencies konfigureras.
- Migrationer har statiskt verifierats och har metadata för syfte, påverkan, backfill, rollback och verifiering.

## Ej verifierat i denna körmiljö

- SQL-migrationerna har inte körts mot en live PostgreSQL-instans eftersom PostgreSQL/Docker inte fanns tillgängligt.
- Inga provider-E2E kunde köras utan TIC/Freja-tenants, nycklar och certifikat.
- PAdES/DSS/Sweden Connect är fortfarande säkra gränser, inte produktionsintegrationer.
- Skriftliga donortillstånd har uppgetts men själva dokumenten bifogades inte; därför importerades ingen donor-kod.
