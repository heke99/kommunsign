  THIS RUN FOUND TWO PRODUCTION DEFECTS THAT EVERY TEST HAD MISSED.

    Neither SwedenConnectSigningEngine nor PadesValidator registered the
    BouncyCastle security provider. Every Java test passed anyway, because the
    test fixture SigningTestAuthority registers it in a static initialiser — the
    fixture was supplying what production lacked.

    In production: SignService would start, report signingAvailable: true, and
    refuse every signature with an opaque SIGNING_FAILED. The validator would
    report every signature as unverifiable, because sigval-pdf does not throw
    without the provider — it simply recovers no signer certificate, so a broken
    validator is indistinguishable from a bad signature.

    Both now register the provider themselves, re-checked at each use rather
    than only at class load, and SecurityProviderRegistrationTest removes the
    provider before exercising them so the fixture cannot mask it again.

    A third, smaller gap: the signing failure was swallowed with no server-side
    record, so a missing provider and a corrupt PDF produced the identical
    opaque answer. A safe classification is now logged — exception class and a
    recognised condition, never the message, which is the part that carries key
    paths and document content.

PRODUCTION_GO: NO.

  Two separate reasons, and only the second is external.

  First: the signing core has now been run for real and is green, but the
  application-level chain around it (API and workers driving the jobs) has not.
  The real-flow run immediately found two defects that 147 unit tests and 17
  Java tests had all missed, which is the strongest available argument for
  finishing the rest of it before anyone treats the green gates as readiness.

  Second: production requires artifacts no code can supply:

    - a CA-issued signing certificate for the organisation
    - HSM or remote QSCD key protection (production refuses SOFTWARE protection)
    - an RFC 3161 timestamp authority contract
    - TIC/BankID production credentials
    - Kungälv's IdP metadata (EntityID, SSO endpoint, signing certificate)
    - the receiving e-archive's confirmed FGS version and XSD set
    - the hosting platform feeding kommunsign_last_successful_backup_timestamp_seconds

  Each is recorded as BLOCKED_EXTERNAL against the specific requirement in
  docs/compliance/kungalv/EXTERNAL_EVIDENCE_BLOCKERS.md, with the exact blocker.
